# Decisões da configuração do ESLint

Contexto: até 2026-07-27 o `npm run lint` **nunca rodou** neste projeto. O
`.eslintrc.json` estendia `prettier/@typescript-eslint`, que foi fundido em
`prettier` na versão 8.0.0 do `eslint-config-prettier` — o comando abortava com
erro de config antes de analisar qualquer arquivo. Ninguém viu o resultado
desde o commit inicial.

Com a config corrigida, a base acusou **12.449 problemas em 711 arquivos**.
As decisões abaixo tornam o lint utilizável sem gerar um diff de refatoração
gigante (CLAUDE.md II.6 — mínima mudança necessária).

## Regras desativadas ou rebaixadas

### `no-promise-executor-return: "off"`

O airbnb-base proíbe retornar valor do executor de uma Promise. Isso torna
ilegal o idioma padrão de sleep em JavaScript:

```ts
await new Promise(resolve => setTimeout(resolve, ms));
```

O valor de retorno do `setTimeout` (um handle de timer) é descartado, então não
há bug — só ruído. O sleep é usado no delay de digitação humana
(`humanTypingDelay.ts`), que é peça central do endurecimento anti-banimento.

### `no-await-in-loop: "warn"` (era `error`)

A regra existe para pegar await sequencial onde `Promise.all` resolveria — um
padrão real de lentidão (CLAUDE.md XI.3).

Mas em várias partes deste projeto a sequencialidade é **obrigatória**, não
acidental: envio de mensagens pelo WhatsApp precisa respeitar ordem e intervalo
entre mensagens (paralelizar é justamente o comportamento que dispara detecção
de bot na Meta), e a renovação do indicador "digitando…" é um laço temporal por
definição.

A base tem 131 ocorrências. Como `error`, a regra bloquearia todo commit que
tocasse esses arquivos; como `warn`, continua visível na saída do lint para
avaliação caso a caso, sem travar o portão.

**Ao ver este aviso em código novo, pergunte:** as iterações são independentes?
Se sim, use `Promise.all` (XI.3). Se a ordem ou o intervalo importa, o await no
laço está certo — siga em frente.

## Por que o lint é incremental

O CI e o hook de pre-commit rodam o ESLint **apenas nos arquivos alterados**,
não na base inteira. Justificativa completa em `scripts/lint-changed.sh`.

Resumo: 74% dos 12.449 problemas são formatação (`prettier/prettier`, `quotes`,
`import/order`). Rodar `--fix` na base geraria um diff de 711 arquivos que
quebraria `git blame` e `git bisect` e tornaria qualquer revisão impossível.
O legado é limpo aos poucos, conforme cada arquivo for tocado por outro motivo.
